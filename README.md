# Kotoba Translate

PLaMo 3 Translate MLX専用の個人向けmacOS翻訳アプリ。SwiftUI + AppKit、ローカルPythonワーカー（mlx-lm）。Apple silicon / macOS 14以降 / Swift 6以降 / uvを使用。

## 起動

```sh
uv sync --python 3.12
swift run KotobaTranslate
```

Finderから起動するアプリを作成する場合:

```sh
zsh scripts/build-app.sh
open "dist/Kotoba Translate.app"
```

現在のCommand Line ToolsのmacOS 27.2 SDKでは`SwiftUIMacros`が欠けており、MarkdownUIの依存先でビルドエラーになります。`scripts/build-app.sh`は、SDKの指定がない場合、インストール済みの26.5 SDKを自動選択します。`--sdk`または`SDKROOT`による明示指定を優先します。手動で指定する場合:

```sh
zsh scripts/build-app.sh --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
```

Python環境はリポジトリ内の`.venv`を参照するため、このディレクトリは残してください。移動した場合は設定のPythonパスを更新するか、アプリを再ビルドしてください。

## リリース版のインストール

1. 起動中のKotoba Translateを⌘Qで終了します。
2. `dist/Kotoba Translate.app`をFinderで「アプリケーション」へコピーします。更新時は既存のアプリを置き換えます。
3. 「アプリケーション」から起動します。必要ならDockに追加してください。

作成済みの`.app`はリリースビルドです。インストーラーや`swift run`は不要です。Pythonはアプリに同梱せず、このリポジトリの`.venv`を参照します。インストール後もリポジトリと`.venv`を残してください。別のPython環境を使用する場合は設定のPythonパスを変更します。モデルの保存場所もそのまま参照するため、モデルは別途残してください。

アプリアイコンの原本は`Assets/AppIcon.png`に保存し、ビルド時に標準サイズの`.icns`を生成します。

## モデル

モデルはユーザーが別途ダウンロードします。公式の`pfnet/plamo-3-translate-{0.8b,2b,8b,31b}-MLX-4bit`など、PLaMo 3 TranslateのMLXモデルを使用してください。GGUFや元のTransformersの重みには対応しません。

「モデルを追加…」からローカルディレクトリを登録し、設定（⌘,）でタグを編集できます。モデルの重みだけでなく、tokenizer、`config.json`、`modeling_plamo_mlx.py`などモデルに付属するファイルも必要です。公式手順どおり`trust_remote_code=True`でディレクトリ内のPythonコードを読み込みます。翻訳実行中のHugging Faceアクセスはオフラインモードで無効化しています。

## 操作

- 起動後、最初の原文をApple標準のNaturalLanguageで判定し、日本語なら翻訳先を英語、それ以外なら日本語へ自動設定します。貼り付け、サービス経由の選択テキスト、記事取得、PDF取り込みに共通です。同じ起動中は原文を消去・差し替えしても2回目以降の自動変更は行いません。先に翻訳先を手動選択した場合もその選択を保持します。判定にPython・翻訳モデルは使用しません。
- 他のアプリで文章を選択し、「サービス」→「Kotoba Translateに送る」を実行すると、原文欄に選択テキストを入れてアプリを表示します。原文欄にフォーカスが移るため、Enterで翻訳を開始できます。取り込みだけではモデル読み込み・翻訳を開始しません。取り込み時に進行中の翻訳・記事取得は中止し、前の訳文は消去します。
- ショートカットキーの設定: 更新したアプリを「アプリケーション」に配置して一度起動し、macOSの「システム設定」→「キーボード」→「キーボードショートカット」→「サービス」で「Kotoba Translateに送る」を有効にして、任意のキーを割り当てます。サービスがすぐに表示されない場合は、利用元アプリを再起動するか、macOSに再ログインしてください。選択テキストのサービスに対応するアプリで利用できます。
- 起動時は原文の編集欄にフォーカスを置き、そのまま⌘Vで貼り付けてEnterで翻訳できます。URL入力欄は通常表示せず、下部の「記事を取得」から開きます。
- 「記事を取得」で開いた「記事のURL」にHTTPSのURLを入力し、「取得」（またはURL欄でEnter）を押すと、SwiftReadabilityで記事本文を抽出し、HTMLToMarkdownでMarkdownへ変換して原文欄を置き換えます。成功時はURL入力を閉じて原文欄にフォーカスを戻します。取得だけでは翻訳・モデル読み込みを開始しません。内容を確認・編集してから「翻訳」を押してください。取得中は「中止」で取り消せます。原文を編集した場合も取得を取り消し、編集内容を保持します。失敗時は元の原文を残します。
- 記事取得はHTMLページ（上限5MB）に対応します。ログインやJavaScriptによる本文の表示が必要なページには対応しません。URL・取得した本文は保存せず、通信のディスクキャッシュも使用しません。
- 「ファイルを取り込む…」でローカルPDFを選ぶと、Markdownへ変換して原文欄を置き換えます。取り込みでは翻訳・モデル読み込みを開始しません。文字情報のあるページはPDFKitで直接抽出し、文字情報のないページだけApple Visionの端末内OCRを使用します。追加ダウンロード・Python起動・ネットワーク通信は不要です。OCRは精度優先の認識を使い、描画を長辺最大2,200pxに抑えて速度とメモリ使用量を調整します。
- PDF取り込みはバックグラウンドで行い、ページ進捗と「中止」を表示します。取り込み中の原文編集やサービスからの入力でも取り消し、古い結果で上書きしません。失敗・中止時は元の原文を残し、成功時は前の訳文を消去して原文へフォーカスを移します。PDF・生成したMarkdownは保存しません。上限は200MB・1,000ページ・抽出後200万文字。パスワード保護PDFは解除してから取り込んでください。
- PDFの文字サイズから見出しを推定し、段落・箇条書き・CJKの折り返しを整えます。画像自体は取り込まず、表・数式・複雑な段組み・縦書きの再現は保証しません。OCRの対応言語・精度はmacOSのVisionに依存します。取り込み結果を確認・編集してから翻訳してください。
- 原文・訳文の言語を選択。原文は自動検出も可能。公式の53言語に対応。
- Enterで翻訳、Shift+Enterで改行、⌘Enterでも翻訳。IME変換中のEnterは変換確定。
- 日本語への翻訳では「指定なし」「常体」「敬体」を選択。
- 「翻訳オプション」で絵文字付きプリセットと追加のコンテキスト、グローバル辞書の適用、Max tokens、Temperatureを指定。プリセットの場面説明と追加コンテキストを合わせて翻訳に使用します。辞書の用語対は設定で編集。
- 標準プリセットは💬日常・カジュアル、🎩日常・フォーマル、🎓論文、🛠️技術文書、💼仕事、📱SNS。場面を選ぶ構成は[nani.now](https://nani.now/)を参考にしています。内容は[PLaMo公式のcontext仕様](https://huggingface.co/pfnet/plamo-3-translate-0.8b-MLX-4bit/blob/main/README_ja.md#参考文脈を渡す)に合わせ、文章の種類・相手との関係・場面を各2文で説明しています。「設定」→「プリセット」で自作プリセットの絵文字・名前・場面説明を作成・編集・削除できます。自作プリセットとアプリ別の設定を保存し、翻訳画面の追加コンテキストや選択状態は保存しません。
- 同設定の「アプリ別の自動適用」でアプリを追加し、プリセットまたは「自動適用しない」を指定できます。サービスとそのキーボードショートカットからテキストを受け取る際、ウィンドウを表示する前の前面アプリ（本アプリへ切り替わった場合は直前のアプリ）のBundle IDで照合します。macOSサービスは送信元IDを直接提供しないため、この判定は取得できる範囲での推定です。未登録・不明・「自動適用しない」の場合は現在の選択を維持します。Shortcuts／Automatorが前面の場合、元アプリは推定せず自動適用を見送ります。アプリアイコンからの通常起動には自動適用しません。
- 「ファイルを取り込む…」はPDFに加え、TXT・Markdown・CSV・TSV・JSON／JSONL・YAML・TOML・XML・HTML・ログ・INI・SRT・VTTなどのプレーンテキストにも対応します。テキストは内容や改行をそのまま取り込みます（HTMLの本文抽出や表の変換は行いません）。UTF-8、BOM付きUTF-16／UTF-32、Shift JISに対応し、上限は8MB・200万文字。バイナリや空のファイルはエラーとし、原文を保持します。バックグラウンドで読み込み、中止・原文編集・サービス入力時は古い取り込み結果を破棄します。
- 下部の「オプション」ボタンで翻訳オプションを開閉。⌥⌘Oでも開閉。
- 設定の「文字」で原文・訳文それぞれのフォント、サイズ（10〜40pt）、書体、文字色を変更。「書体」には選択したフォントに実在するスタイル（ヒラギノのW3・W6、MenloのRegular・Boldなど）を表示し、その書体を直接使用します。フォントを変更した場合は新しいフォントの標準書体へ戻ります。文字色は「リセット」でシステム標準へ戻せます。設定は保存され、生テキストとMarkdownプレビューに反映。
- 原文下部に文字数と概算トークン数を表示。文字数は書記素単位。トークン数はCJK文字を約1.5トークン、それ以外をUTF-8の約4バイトで1トークンとして推定する目安。モデル・Python・tokenizerは使用しません。Context・辞書・指示トークンは含まないため、実際の入力トークン数・上限判定には使用しません。入力後150ms待ってバックグラウンドで集計。
- 原文・訳文の目のアイコンでMarkdown表示へ切り替え、テキストのアイコンで戻る。初期表示は生テキスト。MarkdownUI（swift-markdown-ui）を使用し、プレビューは選択時のみ生成。内容が変わらないプレビューは状態・統計の更新時に再解析しません。コピーは常に生テキスト。
- 翻訳オプション内でタグ名からモデルを選択。緑の点は読み込み中・読み込み済みを示し、「解放」でモデルを解放。設定の「一般」→「モデル」→「デフォルト」で起動時に選択するモデルを指定。未指定・削除済みの場合は先頭のモデルを選択します。選択だけではロードしません。
- 各テキスト欄の上に言語・プレビュー・消去／コピーを配置。下部に原文の文字数と生成統計を表示。訳文右上のボタンでコピー。原文・設定は生成中も編集可能で、実行中の翻訳には開始時点の値を使用。
- 「中止」はPythonプロセスごと終了しモデルを解放。途中までの訳文は残す。
- 設定で翻訳終了後の自動解放時間を選択。オプション内の「解放」でも即時解放。
- 読み込み中、入力処理進捗、生成中の訳文・トークン数・生成速度を表示。完了時の所要時間は読み込み・入力処理を含む。統計にカーソルを重ねると入力トークン数などを表示。Max tokensで切れた場合は「生成上限に到達」と表示。

アプリを開くだけではPythonもモデルも起動しません。同じモデルは解放まで再利用し、別のモデルやPython環境に切り替えた場合は次回翻訳時にワーカーを再起動します。生成時のKVキャッシュはリクエストごとに独立しています。履歴機能はありません。原文・訳文・Contextはディスクに保存せず、モデルの登録・辞書・Pythonパス・解放時間・デフォルトモデル・フォント設定（書体・文字色を含む）、ローカルAPIのポート・APIキーをUserDefaultsに保存します。

## ローカルAPI（OpenAI互換）

ツールバーの「ローカルAPI」を開き、「サーバーを開始」を押します。開始だけではPythonもモデルも起動しません。アプリが起動している間、`127.0.0.1`だけで接続を受け付けます（LAN公開・自動起動はしません）。

サーバーの起動中・受付中はメニューバーにアイコンを表示します。受付状態・接続先・実行中／待機中／完了件数を確認でき、各画面の表示、サーバー停止、アプリ終了を操作できます。赤い閉じるボタンでウィンドウを閉じてもサーバーは継続し、Dockのアイコンを押すと翻訳画面を開き直せます。

ブラウザ拡張などのOpenAI互換プロバイダーに次を設定してください。

- Base URL: `http://127.0.0.1:8765/v1`（ポートは変更可能）
- APIキー: 「接続」タブの「APIキーをコピー」で取得
- モデル: `plamo-translate`（「接続」タブで選んだモデル）。`GET /v1/models`のID、または設定の一意なタグも使用可能
- エンドポイントをフル指定するクライアント: `http://127.0.0.1:8765/v1/chat/completions`

`POST /v1/chat/completions`の通常JSON応答と`stream: true`のSSE（delta、finish_reason、`[DONE]`）に対応します。すべての実リクエストで`Authorization: Bearer <APIキー>`が必要です。CORSプリフライトにも対応します。ブラウザ側でローカルネットワークの許可が必要な場合は許可してください。

「リクエストJSON」タブで原文・言語・文体・Context・辞書適用・生成設定・ストリーミングを選び、「JSONを生成」でJSONを組み立てます。JSONは編集・コピーでき、サーバー起動中は「送信して試す」で実際のHTTP応答を確認できます。フォームの変更は再生成すると反映されます。APIキーはJSONには含めず、HTTPヘッダーに設定します。

```json
{
  "model": "plamo-translate",
  "messages": [{"role": "user", "content": "Hello, world!"}],
  "target_lang": "ja",
  "source_lang": "",
  "form": "polite",
  "use_glossary": true,
  "max_tokens": 2048,
  "temperature": 0,
  "stream": true
}
```

`user`の本文そのものを翻訳します。対応するのは1件のuserメッセージと任意のsystem/developerメッセージ（文字列のみ）です。system/developerと追加の`context`はPFMLの参考情報として渡します。会話履歴・画像・ツール呼び出し・任意の指示実行には対応しません。拡張側で翻訳指示をuser本文へ埋め込むと、その指示文も翻訳対象になるため、原文だけをuserに渡せる設定を使用してください。

拡張フィールド`source_lang`・`target_lang`・`form`を省略すると「接続」タブの値を使います。言語はアプリと同じ53言語のコード（`ja`、`en`など）。原文の空文字は自動検出、文体は日本語のみ`plain`/`polite`です。`use_glossary`は既定でtrue、`glossary: [{"source":"原語","target":"訳語"}]`でそのリクエストだけの辞書へ置き換えられます。生成上限は`max_completion_tokens`または`max_tokens`（既定2048、前者優先）、temperatureは既定0です。

通常は翻訳画面と1つのワーカーを共有します。リクエストが重なると最大32件の待ち行列で受け付け、必要に応じて独立したPythonワーカーを追加します。「混雑時の処理」で最大並列数（1〜4、初期値1。既存の設定は保持）、確保するメモリの余裕（初期値4GB）、バッテリー駆動中の増加可否を設定できます。まずサーバー・ブラウザ拡張の両方を1並列にし、2以上は同じページ全体の完了時間を比較して選んでください。1並列では各リクエストのモデル容量調査も省きます。上限到達時は429（`Retry-After: 1`）を返します。

追加前に電源・低電力モード・温度・メモリプレッシャーと利用可能メモリを確認します。バッテリー駆動中は既定で1並列、低電力モード・高温・メモリプレッシャー時も1並列です。モデルの重みサイズに余裕を加え、最大32KのKVキャッシュとランタイム分を保守的に見積もり、設定したメモリの余裕を残せる場合だけ追加します。見積もれないモデルは追加せず順番に処理します。モデル読み込みは一度に1つずつ行い、サーバー開始だけではロードしません。利用可能メモリは空きページと回収可能な非アクティブページから求める目安で、将来のメモリ使用量を保証する値ではありません。

需要が落ちると追加ワーカーは30秒の待機後にプロセスごと解放します。共有ワーカーは既存の自動解放設定に従います。省電力・高温・メモリプレッシャー時は追加の待機ワーカーを早めに解放し、実行中の翻訳は完了させます。接続切断は該当リクエストだけを中止・解放し、サーバー停止は待機中を含む全APIリクエストを中止します。通常画面で翻訳中の場合はAPIリクエストを待機させます。通常画面の翻訳はサーバー停止の影響を受けません。

並列ごとにモデルをロードするため、メモリ消費が増えます。同じGPUを共有するため、モデルや原文の長さによっては並列化で遅くなる場合もあります。実行数・待機数・モデル数・追加を制限している理由を画面で確認し、遅くなる場合は最大並列数を1に戻してください。

通常JSON応答には拡張フィールド`timings`を付与します。SSEでは`finish_reason`を持つ最後のchoicesチャンクに付与します。`stream_options: {"include_usage": true}`を指定すると、その後に`choices: []`と`usage`を持つチャンクを送信してから`[DONE]`で終了します。未指定ではusageチャンクを追加しません。

| timingsのキー | 意味 |
| --- | --- |
| `total_seconds` | サーバーの処理開始から翻訳完了まで。HTTP本文の受信・応答の転送・ブラウザ描画は含まない |
| `queue_seconds` | 推論プール受付からワーカー割り当て後の実行開始まで。必要なモデル容量調査も含む |
| `first_content_seconds` | サーバーの処理開始から最初の空でない訳文を受け取るまで。SSEの初期roleチャンクやheartbeatは含まない |
| `worker_seconds` | Python内の処理時間。Python自体の起動は含まない |
| `load_seconds` | Python内でのモデルロードなどの準備時間。ロード済みなら短くなる |
| `prompt_seconds` / `generation_seconds` | MLXのトークン数÷対応する処理速度で求めた入力処理時間・生成時間 |
| `prompt_tps` / `generation_tps` | 入力処理速度・生成速度。待機やモデルロードを含む実効速度とは異なる |

取得できない項目は省略します。各時間には重複する範囲があるため、すべてを足して合計にしないでください。「接続」タブにも直近に完了したAPIリクエストの時間と生成速度を表示します。数値だけをメモリに保持し、原文・訳文・Contextや計測情報をディスクへ保存しません。

ブラウザ拡張を自作する場合は、全タブ共通で同時1件を基準にし、表示領域を優先して段落単位で送信してください。DOM更新の連鎖による再翻訳、同一文章の重複送信、長い翻訳指示やページ全文Contextの毎回送信を避けると、リクエスト数と入力処理を減らせます。処理中の同一リクエストは共有し、訳文キャッシュはメモリ内でモデル・言語・文体・Context・辞書設定ごとに分けます。`stream: true`では受信途中から表示し、最初の非空contentと`[DONE]`を受けた時刻・描画完了時刻を別々に測ってください。短いタイムアウトで切断と再試行を繰り返すとワーカーが終了して再ロードになるため、未送信の不要な仕事を先に除去してください。

HTTPリクエスト上限は1MB、ヘッダーは16KB、受信待ちは15秒、待ち行列と推論を合わせて最大10分です。HTTP/1.1とContent-Lengthを使用し、chunkedのリクエスト送信には対応しません。リクエスト本文・訳文・Context・JSONビルダーの内容・応答は保存しません。ポート・APIキー・最大並列数・メモリの余裕・バッテリー駆動時の設定を保存し、サーバーのモデル・言語・文体の選択は起動中だけ保持します。APIの結果で通常画面の原文・訳文・Contextを置き換えることはありません。

## 実装

Swift Packageとして構築し、MarkdownプレビューにMarkdownUIを使用します。任意のローカルAPIはAppleのNetwork.frameworkで受付し、推論は専用Pythonプロセスと標準入出力のJSON Linesで通信し、読み書き・推論はメインスレッド外で実行します。生成テキストは約20HzにまとめてUIへ反映します。中止・自動解放・アプリ終了時にはプロセスを終了してMLXメモリを解放します。

公式推奨のPFML3を直接構築し、`dataset=translation`、`source_lang`、`target_lang`、`context`、`glossary`、日本語限定の`form`を反映。BOSは1回だけ付加し、`<|plamo:tag|>`と`<|plamo:bos|>`を終了トークンに追加します。予約PFMLトークンを入力に含む場合はエラーにします。入力と生成上限の合計は32,768トークン以内に制限します。

依存バージョンは公式MLXモデルの`plamo_mlx_runtime`に合わせています。モデルを用いた実推論にはダウンロード済みのモデル一式が必要です。

記事取得の検証（XCTest・モデル・Pythonは不要）:

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk zsh scripts/check-article.sh
```

引数にHTTPSの記事URLを渡すと、実際の取得からMarkdown変換まで追加で確認します。URL検証、本文抽出、見出し・強調・相対リンク、日本語文字コード、空本文のエラーを検証します。

PDF取り込みの検証（合成PDFで文字抽出・画像ページのOCR・Markdown整形・空本文・中止を確認）:

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk zsh scripts/check-pdf.sh
```

ローカルAPIの通信・ワーカー制御の検証（先にリリースビルドが必要。実モデルは使わず、JSON Linesを返す模擬ワーカーを使用）:

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk zsh scripts/check-server.sh
```

認証、CORS、モデル一覧、通常応答/SSE、入力検証・サイズ制限、待ち行列・上限超過時の拒否、独立ワーカーの並列実行、電源・温度・メモリによる制限、中止・切断・サーバー停止、ワーカー異常終了、アイドル解放と再ロード、通常画面の本文保持を確認します。実モデルによる推論・各ブラウザ拡張との互換性は別途確認が必要です。
